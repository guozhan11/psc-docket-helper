# PSC Docket Helper

An independent beta AI assistant for exploring District of Columbia Public Service Commission dockets, regulatory filings, and public records.

## What It Does

- Searches inside indexed public filing PDFs, not just filing titles.
- Answers filing-content questions with document names, PDF page numbers, and official links.
- Searches **every indexed case** for cross-case questions, not a sample.
- Retrieves current notices and regulatory news from the official DCPSC website.
- Keeps separate chat sessions in the user's browser.
- Publishes corpus freshness and coverage through a fail-closed health endpoint, watched by an alert that files an issue when it degrades.
- Protects the production chat API with request limits, Cloudflare rate limiting, and Turnstile.

## Questions That Work Well

- `In FC1176, what drove Pepco's 2025 O&M expense variance?`
- `Which FC1176 filings discuss bad debt or uncollectible accounts?`
- `Which DC PSC cases discuss low-income residential disconnections?`

A question naming a case number searches that case directly. A question without one searches all 40,000-plus indexed cases, ranks them, and then opens the strongest candidates to verify the actual filing text before answering.

Ranking favours rarer, more distinctive words: a term appearing in most filings — `commission`, `residential` — cannot separate one case from another and is set aside. **The more specific your wording, the better the result.**

A follow-up such as `And for 2024?` continues within the cases just discussed.

## Limits Worth Knowing

- Cross-case answers are ranked shortlists, not exhaustive lists. Confirm anything load-bearing against the linked filing or the official e-Docket.
- Roughly 1% of cases have no extractable text and cannot be reached by content search.
- Answers are generated by a language model from verified excerpts. The excerpts are real and the citations resolve, but whether an excerpt truly answers the question is a judgement the tool does not make for you. **Open the linked filing before relying on an answer.**

## How It Works

Public filing metadata and official links are published first. Four non-overlapping ingestion shards then download PDFs temporarily, convert them into searchable page-level text, and store gzip-compressed, text-only HTML in Cloudflare R2. PDF images, embedded fonts, and layout data are not retained. Sharded per-case manifests hold metadata and search filters without concurrent-write conflicts. The original PDFs are not permanently duplicated in project storage, and scheduled ingestion resumes from its previous checkpoint.

Cross-case questions are served by an inverted term index: 4,096 shards mapping each term to the cases containing it, so a question reads only the shards for its own words and its cost follows the question rather than the corpus. Ranking combines inverse document frequency with a term frequency normalised by case size, so a mid-sized case discussing a topic throughout outranks a two-thousand-filing docket that mentions it once. Terms are indexed by a prefix-preserving stem, so a question about `disconnections` reaches filings that only ever wrote `disconnection`.

The Worker verifies exact matches against the stored page text before OpenAI prepares an answer, and every citation links back to the official PDF at the cited page. No vector database is used.

## Run Locally

Requirements: Node.js, npm, and an OpenAI API key for synthesized answers.

```bash
npm install
export OPENAI_API_KEY="your_api_key_here"
npm run dev
```

Open [http://localhost:3000](http://localhost:3000).

## Checking Retrieval Quality

```bash
npm run eval:validate     # the release question set is well formed
npm run eval:retrieval    # score case-specific retrieval against the local corpus
npm run eval:cross-case   # score cross-case routing against the published index
```

`eval:cross-case` reports how many cases each question reaches, how far the top candidate stands above the rest, and whether rewording a question changes which cases it finds. It imports the Worker's own ranking functions, so what it measures is what production does.
